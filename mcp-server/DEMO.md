# Demo: 使用 AI 赋能 Trustee 可信计算平台

本文档将作为使用 `Trustee MCP Server` 进行能力演示的指南。它以演示文稿的形式组织，包含一系列精心设计的 Prompt，旨在清晰地展示如何通过自然语言与 Trustee 平台进行交互。

---

## Part 1: 开场 (Presentation Start)

### **Slide 1: 标题页**

*   **标题**: `Trustee MCP Server`: AI 驱动的下一代机密计算管理
*   **副标题**: 让安全运维进入自然语言交互时代
*   **演示者**: [您的名字/团队]

### **Slide 2: 当前的挑战**

*   **主题**: 机密计算管理的复杂性
*   **要点**:
    *   **高技术门槛**: 需要深入理解 TEE (SGX, TDX, SEV) 技术细节。
    *   **陡峭的学习曲线**: 学习 Rego 策略语言、理解证明流程对新用户不友好。
    *   **繁琐的手动操作**: 依赖图形界面或命令行工具，操作效率有待提升。
    *   **分散的知识**: 运维知识和安全策略分散在文档和资深员工脑中，难以复用。

### **Slide 3: 我们的解决方案**

*   **主题**: 引入 `Trustee MCP Server`
*   **核心理念**: 将 Trustee Gateway 的强大功能，封装为大语言模型 (LLM) 可理解和调用的工具。
*   **工作模式**:
    *   **用户**: 用自然语言提出需求。
    *   **LLM**: 理解用户意图，选择合适的工具。
    *   **MCP Server**: 执行工具，与 Trustee 交互。
    *   **Trustee**: 完成操作，返回结果。
*   **最终目标**: **ChatOps** - 在聊天中完成所有安全运维工作。

## Part 2: 现场演示 (Live Demo)

### **演示准备**

*   启动一个集成了 `mcp-server` 的 LLM 聊天客户端。
*   确保 `mcp-server` 已正确配置并连接到 `Trustee Gateway`。

### **环节一：基础信息查询 (降低使用门槛)**

这个环节旨在展示最基础的查询能力，体现其对于新用户降低学习门槛的价值。

> **演示 Prompt 1: "你好，请问你能做什么？"**
> 
> *   **预期输出**: LLM 返回 `mcp-server` 所提供的工具列表的自然语言描述，例如："我可以帮助您管理策略、资源、查询审计日志和健康状况等。"

> **演示 Prompt 2: "太好了，请帮我列出当前所有的证明策略。"**
> 
> *   **触发工具**: `list_policies`
> *   **预期输出**: "好的，系统当前有 X 个策略： - policy-1: rego - policy-2: rego ..."

> **演示 Prompt 3: "我想看看 `policy-1` 的具体内容。**"
>
> *   **触发工具**: `get_policy` (policy_id="policy-1")
> *   **预期输出**: 返回该策略的详细信息，包括 Rego 代码内容。

### **环节二：安全审计与智能分析 (提升运维效率)**

这个环节展示如何结合 LLM 的分析能力，从原始数据中发现洞见。

> **演示 Prompt 4: "查询过去一天内所有关于'策略更新'的审计日志。**"
>
> *   **触发工具**: `get_audit_logs` (operation="update_policy")
> *   **预期输出**: 返回匹配的审计日志列表，包含操作者、时间、状态等。

> **演示 Prompt 5 (追问): "分析一下这些日志，有什么潜在的安全风险吗？"**
>
> *   **触发能力**: LLM 的文本分析能力 (不直接调用 `mcp-server` 工具)
> *   **预期输出**: LLM 对上一步返回的日志进行分析，并给出洞察，例如："风险提示：我注意到其中一条策略更新发生在凌晨3点，操作IP地址为非常用地址，这可能是一次未经授权的操作，建议您进行核实。"

### **环节三：策略生成与自动化部署 (核心价值体现)**

这个环节是核心，展示从高层需求到具体策略的自动化生成和部署。

> **演示 Prompt 6: "我们需要一条新的安全策略，它必须满足以下要求：只允许来自'v-prod-sev-snp'仓库的资源通过证明。请为我生成这条策略。"**
>
> *   **触发能力**: LLM 的代码生成能力。
> *   **预期输出**: LLM 生成一段符合要求的 Rego 策略代码，并询问用户是否部署。
> ```rego
> # 生成的策略示例
> allow {
>     input.evidence.quote_type == "sev-snp"
>     input.runtime_data.repo_name == "v-prod-sev-snp"
> }
> ```

> **演示 Prompt 7 (追问): "很好，就用这段代码，创建一个名为 `prod-snp-repo-only` 的新策略。"**
>
> *   **触发工具**: `create_policy`
> *   **参数**: `policy_id="prod-snp-repo-only"`, `content="..."`
> *   **预期输出**: "策略 `prod-snp-repo-only` 已成功创建。"

### **环节四：复合任务自动化 (未来展望)**

这个环节用于展示未来的潜力，即使当前工具不支持，也可以描述其愿景。

> **演示 Prompt 8: "我们即将上线一个新的业务'dragon-slayer'，请为它完成标准的上线流程：注册为可信资源，并应用公司的默认安全策略。"**
>
> *   **触发能力 (未来)**: 复合工具 `onboard_new_app`。
> *   **预期输出**: "正在为您上线新业务 'dragon-slayer' ...
>     1. 调用 `create_resource` 为 'dragon-slayer' 创建资源...成功。
>     2. 调用 `update_policy` 将其纳入默认保护范围...成功。
>     业务 'dragon-slayer' 已成功上线并受安全策略保护。"

## Part 3: 总结与未来 (Conclusion & Future)

### **Slide 4: 总结**

*   **回顾演示**:
    *   通过自然语言，我们轻松完成了**查询**、**审计**、**风险分析**和**策略部署**。
    *   展示了从**高级需求 -> 自动生成代码 -> 一键部署**的全流程自动化。
*   **核心价值重申**:
    *   **为新手**: 大幅降低入门门槛。
    *   **为专家**: 提供前所未有的效率和自动化水平。

### **Slide 5: 未来演进与潜力**

*   **复合工具**: 实现"上线一个新服务"等复杂任务的一键执行。
*   **主动式 AI Agent**: 自动进行安全态势感知、发现潜在威胁并主动告警。
*   **自动化策略演进**: 基于对系统行为的学习，AI 自动建议和优化安全策略。
*   **无处不在的 ChatOps**: 集成到钉钉、Slack 等平台，随时随地进行安全运维。
